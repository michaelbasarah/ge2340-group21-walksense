Try it: load a real window

Sets all sliders to a real 5 s window and shows its true place next to the prediction. Default holds its whole session out, the honest cross-session test. "Same phone only" keeps just that phone's windows in training, as the README recommends (one model per phone). The phone is the real handset (read from each recording's metadata), so "same phone only" is always a same-handset test: ip16 (iPhone17,4) exists on 23 Nov and 24 s2, ip18 (iPhone19,2) on 24 s1 only, the S24 on 24 s1 and 24 s2, the A55 and A56 on 24 s1 only. "Any session" loads a random window from any session; the hold-out below still applies to that window's own session, stop or recording.

Where does the variance come from?

Live demo, not evaluation results. Nested sums of squares of the 5 s window values, for the windows that pass the filters above (session, phone, floor and place; the hold-out of "Try it" is ignored). The same numbers computed in Python are in out/variance_by_place.csv.

Numbers: share of the variance (and sd contribution in the feature's unit)
Method

Per place: mean ± sd of |B| and B_vertical for each phone and session

How each phone performs across sessions

Live demo, not evaluation results. Same kNN recipe as the page, using the current k and weights above (default = learned). Official numbers are in the day-3 README. Windows are 5 s; a recording's result is the majority vote of its windows.

Compare phones side by side

Live demo, not evaluation results. One column per ticked phone (top bar), using the ticked sessions and places, the current k and weights. Recording result = majority vote of its 5 s windows.

What this is not. Wi-Fi is left out (a 100+-dimension vector cannot be slid); the weight normalisation simply ignores it. The |B| group here is the window mean only (fused_knn.py also uses sd, p10, p90 of |B|). Distances and scales use all 2425 windows. Pooling all phones mixes different magnetometers (day-3 README e). One query is one 5 s window, so a single prediction is much noisier than the per-recording numbers in the README.
